Git Branching & Merging Guide

1. What is Git Branching?

A branch in Git is a lightweight, pointer to a specific commit. It represents an isolated line of development. Branching allows you to work on new features, bug fixes, or experiments safely without disrupting the stable main codebase.

Key Commands:

  • git branch feature-name — Creates a new branch named "feature-name".
  • git switch feature-name — Switches your working directory to the specified branch.
  • git switch -c feature-name — Creates a new branch and switches to it instantly.
  • git branch — Lists all local branches in your repository.
# Example workflow: Creating and switching to a feature branch
$ git switch -c feature/login-page
Switched to a new branch 'feature/login-page'

2. What is Git Merging?

Merging is the mechanism that integrates changes from one branch back into another. Once work on a temporary feature branch is completed, tested, and verified, it is combined with the target branch (usually main or master).

The Two Types of Merges:

  • Fast-Forward Merge: Occurs when the target branch has no new commits since the feature branch was created. Git simply moves the pointer forward.
  • Three-Way Merge: Occurs when both the target branch and the feature branch have diverged with independent changes. Git creates a new "merge commit" to tie the histories together.

Crucial Rule: Always check out (switch to) the branch you want to merge into before executing the merge command.

Key Commands:

# Step 1: Switch to your target branch
$ git switch main

# Step 2: Merge the feature branch into main
$ git merge feature/login-page

# Step 3: Delete the feature branch (optional safely)
$ git branch -d feature/login-page

3. Handling Merge Conflicts

A merge conflict occurs when changes are made to the exact same line of the same file across different branches, or if one branch deletes a file that another branch modified. Git will pause the merge process and ask you to resolve it manually.

When a conflict happens, Git modifies the affected file and inserts visual markers:

<<<<<<< HEAD
<h1>Welcome to Our Main Website</h1>
=======
<h1>Welcome to Our Awesome App</h1>
>>>>>>> feature/login-page

How to Fix It:

  • Open the conflicted file in a text editor or IDE.
  • Delete the markers (<<<<<<<, =======, >>>>>>>) and keep the correct code.
  • Stage the fixed file using git add [filename].
  • Finalize the merge by running git commit.
